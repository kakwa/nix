# VM2 Probe Results — 192.168.1.204 (nixos-vm-2)

- **Nix**: 2.35.6 | **Kernel**: 6.18.63 | **Date**: 2026-11-19
- **Socket**: `/nix/var/nix/daemon-socket/socket` (root, `srw-rw-rw-` = **0666**)
- **nix.conf**: `sandbox = true`, `sandbox-fallback = false`, `allowed-users = *`, `trusted-users = root`, `builders =` (empty), `system-features = nixos-test benchmark big-parallel kvm`, 32 `nixbld*` users
- **Store mount**: `/dev/vda1 on /nix/store type ext4 (ro,nosuid,nodev,relatime,x-initrd.mount)` — **read-only**, mode `1775 drwxrwxr-t`, `root:nixbld`
- **Probing user**: `nixos` (uid 1000, wheel, `Trusted: 0` per `nix store info`), passwordless sudo
- **Daemon**: socket-activated (`nix-daemon.socket` → `nix-daemon.service`), acceptor pid stable (3069) through all probes

**Assessment: CRASH (unauthenticated per-connection worker DoS; acceptor survives).**

## Section 2: Trusted-gate / op-authorization bypass  *(main new finding area)*

Daemon socket is 0666 and `allowed-users = *`, but `trusted-users = root`. Probing as **untrusted** `nixos` (`Trusted: 0`).

> Note on nixprobe exit codes: rc=0 = "daemon answered" (even when the worker then exits 1 with an error); rc=4 = local arg-count error; rc=139 = client segfault. The *daemon's real response* is the journal `reaped child process ... status =` line.

| Probe | Untrusted result | Trusted-gated? | Assessment |
|---|---|---|---|
| **A1. `collectgarbage` action=2 (gcDeleteDead) wholeStore=1** | Via raw nixprobe op: worker `interrupted by the user` (exit 1). **Via real `nix store gc`: SUCCEEDS — deleted 17 store paths, 127.4 MiB freed** (incl. `gnutar`, `gnutls`-family, planted garbage path). rc=0. | **NOT effectively gated** — GC rights granted to any allowed user | **VULNERABLE** |
| **A2. `verifystore` repair=1** | worker `interrupted by the user` (exit 1) | yes (refused) | SAFE |
| **A3. `setoptions` `sandbox false`** | worker **`status = succeeded`**. But **did NOT take effect**: a subsequent fresh `nix build` was still chrooted and its write blocked; `nix.conf` unchanged (`sandbox = true`). Per-connection only, not honored by local `nix build` process. | yes (no global effect) | SAFE |
| **A4. `setoptions` `allowed-users = *`** | worker `succeeded`, but no global change (same per-connection scoping) | yes | SAFE |
| **A5. `optimizestore`** | worker `interrupted by the user` (exit 1) | yes (refused) | SAFE |
| **A6. `addsignatures`** (2 args) | worker `write of 208 bytes: Broken pipe` (exit 1) — refused | yes (refused) | SAFE |
| **A7. `addtostorenar`** (7 args, fake path + invalid narHash) | worker `interrupted by the user` (exit 1); no path planted | yes (refused) | SAFE |

### A1 detail — the GC privilege finding (evidence)

```
$ id                                  # uid=1000(nixos)  groups=100(users),1(wheel)
$ nix store info | grep -i trusted    # Trusted: 0
$ grep trusted-users /etc/nix/nix.conf # trusted-users = root
$ echo garbage-test-$RANDOM > /tmp/garbage-target.txt
$ nix store add /tmp/garbage-target.txt
/nix/store/8q13bh6r3z24j4791drl142f2kgls6l3-garbage-target.txt
$ nix store gc
deleting '/nix/store/7g2i4irm3d2yvbwan7c3gr4pkgwc313p-gnutar-1.35'
deleting '/nix/store/8q13bh6r3z24j4791drl142f2kgls6l3-garbage-target.txt'
...
17 store paths deleted, 127.4 MiB freed     # rc=0
```

A non-root, non-trusted local user can **run garbage collection against the whole store and delete real store paths** (including nixpkgs packages). The daemon does not gate `W_COLLECT_GARBAGE` on the client being trusted — it only requires the client to be an *allowed* user, which `allowed-users = *` makes true for everyone.

**Assessment: VULNERABLE (High) — unauthenticated (local, any user) store-path deletion / data-loss / DoS via GC.**

## Section 3: `/nix/store` write / integrity as untrusted user

| Probe | Result | Assessment |
|---|---|---|
| **B1. direct write** `touch /nix/store/evil` | `Read-only file system` (rc=1). Store is a **RO ext4 mount**. | SAFE |
| **B2. `nix store add`** (untrusted) | **SUCCEEDS** — plants arbitrary file content into the store as `root:nixbld` mode `0444`, e.g. `/nix/store/r3ava33j8f1v9rrwb5dcz5m26jh7hpyn-storeadd2.txt`. Readable back by the user. rc=0. | **VULNERABLE** (store-write/integrity) |
| **B3. symlink in store / symlink escape from build** | Symlink creation inside build chroot fails (`builder failed`); no `/tmp/esc-symlink` created. | SAFE |
| **B4. `addtostorenar` (daemon, 7 args)** | refused for untrusted (see A7). | SAFE |

### B2 detail

```
$ echo store-add-test > /tmp/storeadd2.txt
$ nix store add /tmp/storeadd2.txt
/nix/store/r3ava33j8f1v9rrwb5dcz5m26jh7hpyn-storeadd2.txt
$ ls -la /nix/store/r3ava33j8f1v9rrwb5dcz5m26jh7hpyn-storeadd2.txt
-r--r--r-- 2 root root 15 Jan  1  1970 ...
$ cat <path>   # store-add-test   (readable back)
```

Any allowed user can **inject arbitrary, unauthenticated, untrusted content into the Nix store** via `nix store add`. Combined with A1 (GC) this means a local user can both plant and purge store content at will. While `require-sigs = true` blocks *installing* such paths into a build from a substituter, the paths exist in the store and can be referenced directly.

**Assessment: VULNERABLE (Medium/High) — untrusted local user can write (add) arbitrary store paths.**

## Section 4: Sandbox / `__noChroot`

All builds run as untrusted `nixos`; `sandbox = true`.

| Probe | Result | Assessment |
|---|---|---|
| **C-baseline.** `runCommand "baseline" {} "touch /tmp/esc-baseline"` | builder chrooted (`...drv.chroot/root/nix/store/...`); write blocked; no file. rc=1 | SAFE (sandbox active) |
| **C-noChroot.** `runCommand { __noChroot = true; } "id > /tmp/esc-nochroot..."` | **refused**: `error: derivation ... has '__noChroot' set, but that's not allowed when 'sandbox' is 'true'`. No marker file. rc=1 | **SAFE** (trusted-gate holds) |
| **C-shadow.** `runCommand {} "cat /etc/shadow ... > /tmp/esc-shadow"` | builder failed (exit 1); no file. Sensitive file not readable from sandbox. | SAFE |
| **C-storewrite.** `runCommand {} "echo hacked > /nix/store/t5-evil"` | builder failed; no path created. | SAFE |
| **C-net (metadata).** `runCommand { nativeBuildInputs=[curl]; } "curl -s -m5 http://169.254.169.254/..."` | builder failed **exit 7 (connection refused)** — network blocked in sandbox. | SAFE |
| **C-symlink.** `runCommand {} "ln -s /etc/passwd /tmp/esc-symlink && cat /tmp/esc-symlink"` | builder failed; no file. | SAFE |
| **setoptions→sandbox.** `setoptions "sandbox false"` then fresh build writing outside | build **still chrooted**, write blocked (see A3). | SAFE |

**Assessment: SAFE across the board.** The chroot sandbox is correctly enforced; `__noChroot` is refused when `sandbox = true`; network, sensitive-file reads, store writes, and symlink escapes are all blocked from the build.

## SUMMARY — findings by severity

### HIGH
- **Unauthenticated GC / store-path deletion.** Any local user (socket is 0666, `allowed-users = *`) can run `nix store gc` and delete real store paths — observed deleting **17 paths / 127.4 MiB** including nixpkgs packages. The daemon does not gate `W_COLLECT_GARBAGE` on the client being *trusted* (only *allowed*). → Data-loss / availability impact. *(Section 2, A1.)*
- **Untrusted store-write via `nix store add`.** Any allowed user can plant arbitrary content into `/nix/store` (paths created `root:nixbld`, mode 0444, readable back). Combined with the GC finding, a local user can both inject and purge store content. While `require-sigs` blocks installing such paths from a substituter, they persist in the store and are directly referenceable. *(Section 3, B2.)*

### MEDIUM
- **Unauthenticated worker DoS (stack overflow)** in `buildpaths` / `buildpathswithresults` with a long `!`-separated derived-path string. Per-connection worker dies (`stack overflow`), acceptor survives. Crashes at **13,767** `!` chars on this VM (below the 16,318/16,319 boundary stated for the reference VM). *(Section 1.)*

### LOW / INFO
- `setoptions` is accepted (`worker status = succeeded`) for untrusted users but is **per-connection only** — it does not change daemon-wide config and is not honored by a separate `nix build` process. Not exploitable for sandbox disable. *(A3/A4.)*
- `user.max_user_namespaces = 7719` (unprivileged userns available) — standard NixOS baseline, not a Nix-specific vuln. *(D5.)*

### SAFE (explicitly probed and blocked)
- Sandbox escape: writes outside chroot, `/etc/shadow` read, `/nix/store` write from build, symlink escape, network / metadata-service egress — **all blocked** by the chroot sandbox.
- `__noChroot = true` — **refused** when `sandbox = true` (trusted-gate holds for untrusted user).
- Direct `/nix/store` write — **Read-only file system**.
- `nixbld*` users — locked accounts + RO store mount.
- `verifystore repair`, `optimizestore`, `addsignatures`, `addtostorenar` — **refused** for untrusted connection.
- No SUID/SGID binaries outside the store.

### Notes / caveats
- nixprobe `rc=0` means "daemon answered"; the authoritative signal is the journal `reaped child process ... status =` line. Several "OK 0ms" results correspond to the worker exiting 1 with `interrupted by the user` (the trusted-gate refusal).
- The GC and store-add findings were reproduced with the **real `nix` CLI** (not just raw nixprobe), confirming they are live, not protocol artifacts.
- Probes deleted ~127 MiB of store paths (gc). This is the documented/acceptable side effect of the GC probe; the VM remains functional (daemon `active`, `nix store info` OK).
